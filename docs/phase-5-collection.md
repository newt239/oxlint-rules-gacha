# フェーズ 5: コレクションと設定出力

**完了条件**: localStorage への永続化が動き、`.oxlintrc.json` をコピーできる。

引いたルールをコレクションとして貯め、`.oxlintrc.json` に持ち帰れる導線までを 1 セッションで完結させます。ここがサイトの二次目的です。

## データ構造

```ts
type Collection = {
  version: 1;
  obtained: Record<string /* ruleId */, { count: number; firstAt: number }>;
  rulesetVersion: string;
};
```

## タスク

### 永続化

- [ ] localStorage に保存する
- [ ] **`rulesetVersion` が変わっても既存データは破棄しない**。削除済みルールは「過去のルール」としてグレー表示で残す
- [ ] `version` を持たせ、将来のマイグレーションに備える

### コレクション画面（`/[lang]/collection`）

- [ ] プラグイン別セクション。未所持はシルエット表示（**ルール名は伏せる**）
- [ ] ソート: 入手順 / カテゴリ / プラグイン
- [ ] 進捗は全体件数に加えて**プラグイン別・カテゴリ別の達成率**を表示する
  - 870 という分母だけでは動機にならない
  - 例: `eslint 12/187` `jsx-a11y 5/36`

### 設定出力

- [ ] 所持ルールのみから `.oxlintrc.json` を一括生成する
- [ ] 結果カードからは単体の `Copy config` を出す
- [ ] 生成した JSON が正しいことを単体テストで確認する

## テスト

- [ ] 所持ルールから生成した `.oxlintrc.json` が正しい JSON であること
- [ ] `rulesetVersion` が変わっても既存の所持データが失われないこと

## 注意点

- `getServerSnapshot` は静的生成時に呼ばれます。**必ず「未所持」を返すこと。** ここを忘れるとハイドレーション不整合になります。
- コレクションはクライアント側だけの状態です。サーバーへ送らず、他ユーザーと共有する機能も作りません。
