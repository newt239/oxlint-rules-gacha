# フェーズ 8: アクセシビリティとパフォーマンス

**完了条件**: 下記のチェックリストを全て確認し、パフォーマンス予算に収まっている。

Playwright・axe-core・Storybook は入れません。ブラウザ操作と a11y は手動確認とします。自動テストを持たないぶん、リリース前にこのリストを消化してください。

## アクセシビリティ チェックリスト

`jsx-a11y` のルールを扱うサイトである以上、自サイトでは `oxlint` の `jsx-a11y` ルールを全て有効にします。

### 抽選

- [ ] 抽選ボタンは `<button>`。押下中は `aria-busy="true"`
- [ ] 結果は `role="status"`（`aria-live="polite"`）の領域に、演出完了時に一度だけテキストを流す（例: `"no-debugger, correctness"`）
- [ ] 演出中の中間状態（カプセルの落下など）は読み上げない（`aria-hidden`）
- [ ] 連打時は live region の内容をクリアしてから差し替え、読み上げの積み上がりを防ぐ
- [ ] 抽選後もフォーカスは「回す」ボタンに留める。連続操作を妨げない
- [ ] 結果カードはボタン直後の DOM 順に置き、Tab で自然に到達させる

### 演出

- [ ] 画面タップ / Esc / Space でスキップできる。手段は初回のみテキストで案内
- [ ] `prefers-reduced-motion: reduce` で 150ms のクロスフェードに置換される

### 表示

- [ ] テキストのコントラストが 4.5:1 以上（[フェーズ 3](./phase-3-design.md) の表を参照）
- [ ] カテゴリは色 + ラベルで表されている
- [ ] コードスニペットのシンタックスハイライトも背景に対し 4.5:1 を確保

### 言語

- [ ] `<html lang>` が言語と一致している
- [ ] 言語スイッチャーが `hreflang` 付きのリンクである

### 通し確認

- [ ] キーボードのみで「回す → 詳細 → コレクション → 設定コピー」まで到達できる

## パフォーマンス予算

| 指標                    | 目標                                     |
| ----------------------- | ---------------------------------------- |
| トップの初期 JS（gzip） | 100KB 以下                               |
| `rules.index.json`      | 60KB 以下（gzip 15KB 程度）              |
| ルール詳細ページの JS   | 最小限（Client Component を置かない）    |
| LCP                     | 1.5s 以下（4G 相当）                     |
| INP                     | 200ms 以下（ボタン押下から演出開始まで） |
