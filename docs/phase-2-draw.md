# フェーズ 2: 抽選ロジックと最小 UI

演出なしで単発ガチャが動く状態にする。**このフェーズの終わりで一度公開できる状態にしておく**（演出に凝りすぎて止まるリスクを避けるため）。

**完了条件**: 単発が動き、Vitest が通る。

## 抽選の仕様

レアリティ・天井・ピックアップ・重み付けはいずれも持ちません。

1. フィルタ適用後の母集団を確定する（**既定で `nursery` を除外**）
2. 未所持が 1 件以上あれば未所持から一様抽選
3. 未所持がなければ全体から一様抽選

未所持優先により「引けば新しいものが出る」ことが保証されます。

## タスク

### 抽選ロジック

- [ ] `src/features/gacha/draw.ts` に純関数として実装する（DOM 非依存）
- [ ] `src/features/gacha/draw.test.ts` を書く
  - 未所持優先が保証されること
  - 母集団が空のときの扱い
  - コンプリート時の挙動（全所持なら全体から一様抽選）

### ストア

- [ ] `src/lib/persisted-store.ts` を実装する（50 行程度）
  - `subscribe` / `getSnapshot` / `getServerSnapshot` / `set` を持つだけの最小ストア
  - 参照側は `useSyncExternalStore`
  - **`getServerSnapshot` は必ず「未所持・既定フィルタ」を返す**。静的生成時に呼ばれるため、ここを忘れるとハイドレーション不整合になる

### UI

- [ ] `src/features/gacha/GachaMachine.tsx`（`"use client"`）
- [ ] トップは Server Component から `<GachaMachine />` を配置するだけにする
- [ ] ルールインデックスはマウント時に `public/data/rules.index.json` を fetch する。**RSC の props で渡さない**（HTML に全件が埋まり、トップの転送量が跳ね上がる）
- [ ] 結果はページ遷移せず、同一画面上に表示する

  - カテゴリバッジ（色 + テキストラベル）、プラグイン、fix 状況
  - 1〜2 文の要約
  - 悪い例のコードスニペット 1 つ
  - アクション: `View details` / `Copy config` / `Draw again`

### フィルタ

- [ ] プラグイン単位 / カテゴリ単位の抽選対象フィルタ
- [ ] フィルタ設定を localStorage に永続化する

## 注意点

- トップは「回す」以外の選択肢をほぼ持たせません。フィルタ設定・コレクション・About は固定ヘッダと画面下部の控えめな導線に置きます。
- 抽選結果など一時的な状態はコンポーネントローカルで持ちます。永続化が必要なのは「コレクション」と「フィルタ設定」の 2 つだけです。
- この段階からアクセシビリティを入れておくと後が楽です。最低限、抽選ボタンは `<button>`、結果は `role="status"` の領域に流す。詳細は [フェーズ 8](./phase-8-a11y-and-performance.md)。
