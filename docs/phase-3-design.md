# フェーズ 3: デザイントークンと StyleX

**完了条件**: §6 のトークンが適用され、コントラスト確認が済んでいる。

## 方針

「リンターの警告色をお菓子にする」。エラー・警告の色は本来ネガティブな記号ですが、カプセルトイの原色として置き直すとそのままポップな配色になります。**筐体側を暗く沈めることでカプセルの原色が発色します。**

避けるもの: クリーム地 + セリフ見出し + テラコッタ、全面グラデーション、全要素への一律の角丸。

## 完了しているもの

`src/styles/tokens.stylex.ts` に §6.2 のカラートークンを `defineVars` で定義済みです。コントラストも検証済みで、**全色が背景 `#14131F` / `#201E33` に対して 4.5:1 以上**です。

## タスク

- [ ] 筐体・カード・バッジ・ボタンのコンポーネントを StyleX で実装する
- [ ] レイアウトを適用する。**中央揃え 1 カラム、モバイル 375px 基準、デスクトップは最大幅 640px の中央寄せ**
- [ ] タイポグラフィを適用する

  | 用途               | 書体                          |
  | ------------------ | ----------------------------- |
  | 見出し・UI（英語） | Baloo 2 700                   |
  | ルール名・コード   | Geist Mono 500                |
  | 本文               | Baloo 2 400（行長 70 字以下） |

  日本語側（Zen Maru Gothic）は [フェーズ 6](./phase-6-i18n-and-rule-pages.md) で判断します。

- [ ] **ルール名は装飾を加えず字間も詰めない**。設定ファイルに書く文字列そのものなので、正確にコピーできることが最優先
- [ ] カテゴリは色に加えてテキストラベルで表す（色のみに依存しない / WCAG 1.4.1）
- [ ] コードスニペットのシンタックスハイライトも背景に対し 4.5:1 を確保する
- [ ] 新しく色を足した場合はコントラストを再計算する

## 注意点

- 色・フォント・レイアウト値は必ず `tokens.stylex.ts` から参照します。**生の色コードをコンポーネントに直接書かないこと。**
- CSS ファイルを増やさないこと。`src/styles/globals.css` は `@stylex;` ディレクティブとリセットだけを持ちます。
- StyleX のオブジェクトはキーの昇順で書きます（`sort-keys` が効いています）。
